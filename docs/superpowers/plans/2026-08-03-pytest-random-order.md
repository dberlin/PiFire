# Randomized pytest Ordering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every project-configured pytest run randomize module order and test order within modules by default.

**Architecture:** Install `pytest-random-order` in the existing uv `dev` dependency group and enable it through pytest's project configuration. Keep the plugin's default `module` bucket so order coupling is exposed without globally interleaving fixtures; retain the emitted seed for deterministic reproduction.

**Tech Stack:** Python 3.14, pytest, pytest-random-order 1.2.0 or newer, uv

## Global Constraints

- Add `pytest-random-order>=1.2.0` only to the `dev` dependency group; it is not a runtime dependency.
- Enable randomization for ordinary project pytest invocations with `addopts = ["--random-order"]`.
- Use the plugin's default `module` bucket; do not configure `package` or `global` bucketing.
- Do not add `random_order(disabled=True)` markers or other order exceptions.
- Preserve the generated seed in pytest output so `--random-order-seed=<seed>` reproduces failures.
- Any order-dependent failure exposed by the full suite must be fixed at its state-leak source before completion.

- Produces: normal `uv run pytest` invocations that load `pytest-random-order`, use the `module` bucket, and print a reproducible seed.

- [ ] **Step 1: Verify the plugin option is absent**

Run:

```bash
uv run pytest --random-order --collect-only tests/unit/bootstrap/test_smoke.py
```

Expected: pytest exits with an `unrecognized arguments: --random-order` usage error, proving the plugin is not currently installed and active.

- [ ] **Step 2: Add the dev dependency and refresh the lockfile**

Run:

```bash
uv add --dev "pytest-random-order>=1.2.0"
```

Expected: `pyproject.toml` gains `pytest-random-order>=1.2.0` in `[dependency-groups].dev`, and `uv.lock` gains the resolved `pytest-random-order` package plus project dependency-group metadata.

- [ ] **Step 3: Enable random ordering in project pytest configuration**

Add this section after the `dev` dependency group in `pyproject.toml`:

```toml
[tool.pytest.ini_options]
addopts = ["--random-order"]
```

Do not set `random_order_bucket`; omitting it preserves the selected `module` default.

- [ ] **Step 4: Verify the lockfile recreates the environment**

Run:

```bash
uv sync --locked
```

Expected: synchronization succeeds without changing `pyproject.toml` or `uv.lock`.

- [ ] **Step 5: Smoke-test plugin activation and seed replay**

Run:

```bash

```

Expected: pytest reports `Using --random-order-bucket=module`, reports `Using --random-order-seed=314159`, and the smoke test passes.
